Read the existing code before changing it and match its style (pure `core`/`content`/`rules`, `h()` DOM builder, Reader-based parsing, clamped pure actions, parity of desktop and mobile layouts). ## 1. Approved design (chat, 2026-10-17)

- A class (SRD or homebrew vault note) describes **what each level does** as a list of **operations**; subclasses, races, subraces, backgrounds and feats use the same operations. Homebrew classes plug in exactly like SRD ones. Characters record **what was chosen** in a level log.
- HP on level up: the wizard offers **Roll** (hit die + CON, min 1, logged) or **Average** (die/2 + 1 + CON) each time. 1st level of the first class: full die + CON.
- Leveling mode per campaign: campaign note `leveling: xp | milestone` (default milestone). XP mode shows progress to the next level (2014 thresholds) and highlights Level up when crossed; milestone: Level up always available.
- Scope: level-up wizard (multiclassing with prerequisites and multiclass proficiencies, subclass and features, ASI or feat, option picks, new spells, HP) **and** a new-character builder (race, background, ability scores by point buy / standard array / manual, class level 1, starting equipment or gold).
- Undo the last level (one at a time, from the log).
- Content written into the user's vault (not this repo): Blood Hunter (+4 Orders), Tactician (+4 Strategic Focus subclasses), Chromatic Dragonborn, Savage Attacker, Stormweave Voidblade, and Azur (Tactician 6, War Mind) as a sheet. Sources: `/home/aschneider/.claude/jobs/e6629327/tmp/sources/`.

## 2. Operations (the framework)

A level list is `levels: { "<n>": Op[] }` (classes, subclasses) or `grants: Op[]` (race, subrace, background, feat). Every op may carry `id` (stable key; default `<op>-<index>`).

| op | shape | effect | wizard asks? |
|---|---|---|---|
| `grant` | `{ proficiencies?: string[], languages?: string[], spells?: string[], items?: string[], speed?: number, darkvision?: number }` | adds to derived proficiencies/languages; spells always prepared; items added to inventory when the level is applied | no |
| `feature` | `{ name, text?, effects?: Effects, action?: ActionDef }` | adds a feature (text from the note, live); effects join the effects engine | no |
| `resource` | `{ name, max: Formula, reset: short\|long\|dawn\|none, refill?: { on: short, amount: Formula, oncePer?: long } }` | adds a tracked resource; uses stored in `character.uses[<resource id>]` | no |
| `scale` | `{ name, values: { "<level>": string\|number } }` or `{ name, formula: Formula }` | a named per-level value usable in formulas and dice (`{hemocraft-die}`) | no |
| `dc` | `{ name, abil: Abil, alt?: Abil }` | a class DC (8 + prof + mod) and attack (prof + mod) shown on the sheet; `alt` = optional ability toggle stored in `character.choices` | no (toggle in Edit) |
| `modify` | `{ resource?: name, scale?: name, set: Formula }` | changes an earlier resource max / scale from this level on | no |
| `choose` | `{ what: skills\|expertise\|tools\|languages\|option, from?: string[], list?: <option list name>, count: number, swap?: boolean }` | pick N; `option` picks from the class's `options` lists | yes |
| `subclass` | `{}` | pick a subclass note whose `class` matches | yes |
| `asi` | `{}` | +2 one / +1 two abilities (max 20 unless a feature raises it) or a feat | yes |
| `spells` | `{ count: number, cantrips?: number, from: <class id> \| string[], swap?: number, schools?: string[] }` | learn spells into `character.spells` | yes |
| `spellcasting` | `{ abil: Abil, progression: full\|half\|third\|pact\|table, table?: { "<level>": { cantrips?, known?, slots: number[] } \| { pact: { slots, level } } }, list?: <class id> }` | marks the class or subclass as a caster; `table` for custom tables (Scholar, Profane Soul) | no |
| `effect` | `{ effects: Effects }` | always-on effects (e.g. `acAbility: int`) | no |

`Formula`: a number, or a string using `prof`, `level` (class level), `total` (character level), ability mods `str..cha`, scale names, `+ - * /`, `floor()`, `max()`, `min()`. Evaluated by a tiny safe parser (no `eval`). Dice strings may contain `{scale}` placeholders.

Class note top level: `hitDie`, `saves`, `proficiencies` (first class only), `skills: { count, from }` (first class), `multiclass: { requires: { any?: [{abil: n}...], all?: {abil: n} }, proficiencies }`, `equipment: [[option A items], [option B items]] | gold: "4d4*10"`, `options: { <list>: [{ id, name, text, minLevel?, effects?, action? }] }`, `subclassLevel`, `levels`.

`ActionDef`: `{ name, cost?: { resource: name, amount?: Formula } | { selfDamage: dice }, attack?: Formula, save?: { abil, dc: <dc name> }, damage?: dice, heal?: dice, text? }` rendered as buttons in a Features/Actions card; using it spends the resource and rolls.

New effect keywords (extend `Effects` + validator + engine): `acAbility: Abil` (use that ability instead of Dex in the AC formula, still capped by armor), `saveBonus: [{ abils: Abil[], value: Formula }]`, `critRange: number` (with optional `vs: analyzed` note only), `maxScore: { abil, max }`.

## 3. Character data

- Keep `classes: [{ class, subclass?, level }]` (source of truth for levels).
- New `levelLog: LevelEntry[]`, `LevelEntry = { class: string; level: number; hp: { method: "roll"|"average"|"first"|"recorded"; die?: number; gained: number }; choices: Record<string, unknown> }` where choice keys are `<source>:<level>:<op id>` (e.g. `class:blood-hunter:2:fighting-style`). Race/background/feat choices use `race:<id>`, `background:<id>`, `feat:<id>`.
- New `race?`, `subrace?`, `background?` stay ids; new `feats: string[]`, `uses: Record<string, number>` (used counts for derived resources), `choices: Record<string, unknown>` (non-level toggles such as `dc.hemocraft.alt`).
- HP: `hp.max` stays stored. Applying a level adds `gained + CON mod`; an ASI that raises CON's modifier adds the difference x total level. Undo reverses exactly what the entry added.
- Notes without `levelLog` stay valid: features are derived by replaying class ops 1..level with no choices; unresolved choices show as "Choose in Edit mode" and the wizard can resolve them without adding a level.
- All new fields parse with the Reader (wrong types = read-only), are written back only when non-default, and unknown keys are preserved.

## 4. Derivation

`src/core/progression.ts`: `progress(c, registry) -> { features: FeatureRow[]; resources: DerivedResource[]; scales: Record<string, string|number>; dcs: DcRow[]; proficiencies: {...}; languages; options: Record<list, picked[]>; spellcasting: CasterEntry[]; pending: PendingChoice[]; effects: SourcedEffects[]; problems: string[] }` replaying race, subrace, background, feats and each class's levels 1..n (and its subclass levels) in log order. `derive.ts` consumes it: AC uses `acAbility`, saves get `saveBonus`, resources merge with the manual `resources`, spell slots combine casters (2014 multiclass table; `third` and Profane Soul style pact contributions via `table`), skills/expertise from choices, class DCs listed.

## 5. Leveling

`src/core/levelup.ts`:
- `levelOptions(c, registry)`: classes you can take (current classes + others meeting `multiclass.requires`), with reasons when not.
- `planLevel(c, classId, registry) -> LevelPlan { steps: Step[] }` where steps are HP plus every asking op for the new class level (and subclass level, and ASI/feat follow-ups such as a feat's own choices).
- `applyLevel(c, plan, answers, registry, rng?) -> { value: Character; entry: LevelEntry; summary: string[] } | { error }`; validates answers (counts, prerequisites, max 20, no duplicate skills).
- `undoLevel(c, registry) -> Character` reverses the last entry.
- XP: `XP_THRESHOLDS` (2014) and `levelFromXp`.
- Campaign `leveling` field (validator) and `ctl.levelingMode()`.

## 6. UI

- Desktop: **Level up** button in the pinned header (and **Undo last level** in Edit mode); mobile: in the More tab and pinned bar. XP progress bar when the campaign uses XP.
- Level-up panel: step pages with Back/Next: class (with multiclass reasons), HP (Roll / Average, shows result), one page per asking step (checkbox lists with counts, ASI +2/+1+1 or feat search, subclass cards with hover details, spell picker reusing the add-spell list), summary with Apply.
- New **Features** tab (desktop) / inside More (mobile): features grouped by source (race, background, class levels, subclass, feats) with hover/tap details, class DCs, scales (e.g. "Hemocraft die d6"), derived resources with pips, actions as buttons, pending choices with "Choose".
- New-character builder: command "New character (builder)" and a button on an empty sheet: race -> subrace -> background -> ability scores (point buy 27 / standard array / manual) -> class -> level 1 steps -> equipment (class options or gold) -> name -> creates the note via the host (`host.createNote(path, frontmatter)` implemented in the Obsidian layer) and opens it.
- Parity: every new feature placed in both layouts; extend the parity tests.
