# P2: Main Page Layout and Attack Rows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the four stat tiles in one row, replace the header roll-mode buttons with a three-position slider above Attacks, add a Settings card (Rest mode, Hex / Trad, I roll my own dice), and make each attack one compact line, with a 1H / 2H switch for versatile weapons that knows about shields.

**Architecture:** Layouts can now hold a row of features (`Slot = string | readonly string[]`), which the sheet draws as one grid row; that is how the stat tiles stay four separate features (hide/show and parity keep working). The slider, the Settings card and the attack rows are plain-DOM components in their own `src/ui/*-ui.ts` files. How a weapon is held is stored on its inventory entry (`hands: 2`), read by `buildAttacks` (with the shield state from the gates) and changed by a new `hands` action. The equip and attune actions flip a two-handed weapon back to one hand when a shield goes on.

**Tech Stack:** TypeScript, Obsidian plugin API, plain DOM via `h()`, Vitest + jsdom, esbuild.

**Spec:** `docs/superpowers/specs/2026-10-19-play-surface-design.md`. This plan covers section 1 (main page layout) and section 2 (attack rows), plus the "Adjustments to the agreed redesign" bullets that apply to them.

## Global Constraints

- Plain DOM via `h()`, never innerHTML. Mount roots use `classList`, never `className`.
- Every feature at parity on desktop (hover), tablet and phone (tap), with 44px targets on touch. The layout parity tests place each feature id exactly once per layout (`placed()` in `src/ui/layouts.ts`, checked in `tests/ui/sheet.test.ts`).
- A plugin button rule needs `.fe-sheet button.x` specificity to beat Obsidian's `button:not(.clickable-icon)`.
- Test fixtures are INVENTED: no book or SRD prose and no published stat blocks, because the code is mirrored to a public repo. The invented weapons used here are Ash Cudgel, Glass Saber and Reed Pike. The shield is the existing invented Oak Buckler from `tests/ui/inventory-helpers.ts`.
- Plain words for players who are not rules-savvy: "1H" / "2H" with the titles "One hand" / "Two hands", "Put away your shield to use two hands", never effect keywords or ids.
- Nothing in code names a race, class, feat or item. Versatile is detected from the weapon's properties, never from a name.
- Existing notes without the new fields behave exactly as today: no `hands` means one hand, and no `own-dice` rule means off.
- Commit messages are conventional, and the last line is `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- All existing tests keep passing (about 1500). An existing test changes only where this plan moves the thing it asserts, and each such edit is listed in its task.
- Run order: P1 ui-review-fixes is merged to main before this plan starts. P3 attack-options-and-own-dice, P4 customize and P5 items come after it.

## Review Focus

1. **A note edited by hand that says `hands: 2` while a shield is equipped**: the weapon counts as one hand (one-hand damage, and 2H is greyed out). The sheet does not crash or show two-hand damage. Pinned in Task 4.
2. **Removing an earlier inventory row**: the 2H choice stays with its weapon and does not move to whatever slides into that index. Pinned in Task 5.
3. **Unequipping a two-handed weapon and equipping it again**: it comes back in two hands, because the choice is remembered on the entry. Pinned in Task 5.
4. **Roll mode set on one tab, then a roll on another tab** (the phone's Checks tab): the next roll uses the chosen mode, and the slider snaps back to the middle. Pinned in Task 2.
5. **A stat tile hidden through the sheet's hide list**: the row draws the remaining tiles, and with all four hidden there is no empty row element. Pinned in Task 1.
