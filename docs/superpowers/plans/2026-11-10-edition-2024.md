# 2014 and 2024 rules: tracks, order and gates

This is the top-level plan. It orders two detailed plans and the release steps around them. Whoever coordinates the work reads this first.

**Spec:** `docs/superpowers/specs/2026-11-10-edition-2024-design.md` (its last section is the note format both tracks build to).

## Tracks

| Track | Plan | Repo and branch | Where it runs |
|---|---|---|---|
| A. Plugin | `2026-11-10-edition-2024-plugin.md` | `/docker/rpg-sheet`, `feat/edition-2024` | this checkout |
| B. Importer | `2026-11-10-edition-2024-importer.md` | `/docker/homelab-config`, `worktree-dnd-compendium` | the worktree `/docker/homelab-config/.claude/worktrees/dnd-compendium` and `/docker/dnd-compendium` |

A and B share nothing but the contract, so they run at the same time. Inside each plan, every task names the tasks it depends on; tasks with no dependency between them may run at the same time.

## Order across tracks

1. **A and B build in parallel.** B's converters are tested against invented fixtures; A's content code is tested against invented notes in the contract's format.
2. **B builds both libraries locally** into `/docker/dnd-compendium/out` and verifies them by script. Nothing has left this machine yet.
3. **Contract check (mine).** A script feeds a sample of B's real 2024 output (every class, every background, a spread of the rest) through A's validators from a built checkout and lists what comes back unusable. Each failure is either an importer fix or a plugin fix; none is waved through. The sample stays in `/docker/dnd-compendium`; only counts are reported.
4. **Render check (A).** Gallery shots on three layouts go to scratch for the owner.
5. **Docs (A).** `docs/USING.md`, then `docs/IMPORTING.md` once B's commands are final.
6. **Review.** A fresh reviewer per track reads the whole branch against its plan and the spec before anything is pushed.

## Gates that wait for the owner's words

| Step | Needs |
|---|---|
| Push `feat/edition-2024` and open the PR against `main` | reviewed branch (covered by the job's authorization) |
| Push `worktree-dnd-compendium` | reviewed branch (covered by the job's authorization) |
| Re-sync the existing libraries with their edition stamp | the diff shows the stamp and tag are the only change; then the owner's go, as for any re-import |
| Merge the PR to `main` | the owner's words |
| Deploy to the vault with `scripts/deploy-vault.sh` from a clean `main` | the owner's words |
| Sync `compendium/5e/WotC 2024` to the vault | the edition-aware build is deployed first (see the spec, "Order of release") |
| Public mirror | sanitized sync into the staging tree, a separate agent's audit, then push; never by hand |

Never force-push. Never stash or overwrite the owner's uncommitted edits in the main homelab-config checkout.

## What does the work

In this order of preference, per the job's instructions: plain scripts and tools first (the importer, the test suites, the Playwright gallery, diff); the local NanoClaw tier for bulk second looks at importer output, whose answers are drafts to be checked; Claude for building, judging and review. No step in either plan needs a GPU model.

## Final report covers

The design chosen and who chose each part; what was imported (counts per type, what is on Needs Review); test, typecheck and build results for both tracks; which resource did what; what is pushed and where (branch and PR links); what is waiting for the owner's words; one recommended next step.
